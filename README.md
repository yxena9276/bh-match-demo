# BH Match · 零件组合匹配

一个用于演示零件组合精确检索的中文网页应用。输入完整的零件号及数量，查找对应的 BH 代号；没有匹配时，可在当前浏览器中创建新组合。

项目采用原生 HTML、CSS 和 JavaScript，可部署到 GitHub Pages，无后端和运行时第三方依赖。

## 功能

- **精确匹配**：零件号及数量全部一致才匹配，输入顺序不影响结果。
- **便捷输入**：支持粘贴 Excel 两列，或使用逗号、顿号、空格分隔的零件号。
- **数量合并**：重复出现的零件自动汇总数量；未填写数量时按 1 计算。
- **本地新增**：未匹配的清单可创建新 BH，相同组合复用已有代号。
- **组合库**：搜索 BH 或零件号，载入已有清单，复制匹配结果。
- **数据导出**：导出当前浏览器可用的组合明细 CSV。
- **响应式界面**：适配桌面与手机，支持键盘操作。
- **BH 相似度点云**：用二维投影探索组合相似性，点击节点查看相近 BH、共同零件及数量差异；本地新增组合自动加入。

> **数据保存说明：** 原始示例随网页提供，新增组合保存在当前浏览器的 localStorage 中。新增数据不会写入 GitHub，也不会同步给其他访问者。刷新页面可保留记录，清除站点数据或使用隐私浏览可能导致记录丢失。

## 使用示例

在页面中点击“载入匹配示例”，或粘贴以下内容：

```text
BZ1100001    1
BZ1300006    1
BZ1300011    1
```

点击“查找对应 BH”，原始示例中的匹配结果为 `BH1720001`。

也可以只输入零件号，数量按 1 计算：

```text
BZ1100001、BZ1300006、BZ1300011
```

在初始示例中，单独输入 `BZ1200003` 不会匹配已有组合，可用于体验“创建新 BH”。创建前请核对页面展示的完整清单。

## BH 相似度点云

组合库下方提供相似度点云，每个点代表一个 BH。可切换焦点及对比对象，查看最近的组合和逐项明细，也可将焦点清单载入原有精确匹配流程。

- **数量相似**：对每种零件取两套清单数量的较小值并求和，除以较大值之和（数量加权 Jaccard）。
- **种类重合**：共同零件种类数除以两套清单合计的不同零件种类数，忽略数量（Jaccard）。
- **二维位置**：对所选相似度的距离 `1 − 相似度` 进行经典多维尺度分析（MDS），位置为近似；重叠点可能轻微错开，以实际分数和明细为准。
- **交互**：点击节点或使用下拉框选择 BH；调整阈值仅改变连线，不改变投影位置；支持鼠标拖动平移、按钮缩放及重置视图。
- **显示范围**：最多显示 80 个 BH；超过时展示焦点及其最相近的组合。相似度与布局优先在 Web Worker 中计算。

相似度仅辅助探索，创建或复用 BH 仍按全部零件号与数量完全一致判断。即使“种类重合”为 100%，数量也可能不同。

## 精确匹配规则

| 输入情况 | 处理方式 |
| --- | --- |
| 相同零件及数量，顺序不同 | 匹配同一 BH |
| 缺少或增加任一零件 | 不匹配原组合 |
| 任一零件数量不同 | 不匹配原组合 |
| 同一零件重复输入 | 合并数量后匹配 |
| 空清单、未知零件、非法数量 | 显示错误，不创建组合 |

零件号区分大小写并保留前导零。数量为正整数，单种零件合并后最多 10 亿；单次输入最多 2,000 项。

## 本地运行

需要 Git 和 Node.js 22 或更新版本。

```sh
git clone https://github.com/yxena9276/bh-match-demo.git
cd bh-match-demo
npm start
```

打开终端显示的地址：<http://127.0.0.1:4173>。

无需执行 `npm install`。请通过本地 HTTP 服务访问页面，直接打开 HTML 文件可能无法加载示例数据。

运行测试：

```sh
npm test
```

测试覆盖完整匹配、输入解析、数量合并、数据校验、本地保存、模拟并发提交及静态资源路径。

## 部署到 GitHub Pages

1. Fork 本仓库，或将项目上传到自己的 GitHub 仓库。
2. 在仓库 **Settings → Pages → Build and deployment** 中，将 **Source** 设为 **GitHub Actions**。
3. 在 **Actions** 中选择 **Test and deploy demo to GitHub Pages**，点击 **Run workflow**；向 `main` 分支推送提交也会触发部署。
4. 测试和部署成功后，从工作流的部署结果中打开网站。

工作流配置位于 [`.github/workflows/pages.yml`](.github/workflows/pages.yml)，仅发布 `bh-demo/dist`。静态资源使用相对路径，支持仓库子路径部署。

## 使用边界与后续方向

本地新增需要浏览器支持 Web Locks，并通过 HTTPS 或 localhost 访问；不满足条件时，页面会禁用新增功能。同一浏览器、同一站点的标签页通过锁协调写入，这不构成跨设备的数据同步。

当前版本适合演示与小规模本地体验。多人共享和大规模正式数据可沿用界面交互，接入服务端 API 与 PostgreSQL，通过数据库索引、事务、唯一约束及统一编号实现集中管理。
